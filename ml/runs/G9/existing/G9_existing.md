# G9 Arm "existing models": two Roboflow Universe produce detectors vs G3, DEV only (2026-10-14)

**Verdict: neither model beats G3. No promotion.** Both load and run locally on CPU, but their recall is far below G3's on every DEV view.
Where they show fewer false alarms than G3, it is only at DEV-tuned thresholds where their recall collapses (to 4% for snapml and 10% for calories, vs G3's 47% raw correct-frame rate).
Under the "recall must hold" rule, that is a loss, not a win.

Full tables: `results_autogen.md` (generated by `make_report.py`) and `summary.json`. Class maps: `CLASS_MAP.md`, written before scoring. Raw and tracked data with the pre-registered rule: `raw_tracked_dev.json` (`raw_score.py`).

- The VB8 dev web clips have no box GT, so FA there cannot be scored. The weak title check (fraction of frames showing the produce named in the title, 12 single-produce clips) gives G3 0.351, snapml 0.188, calories 0.005 at 0.35. At the tuned thresholds: G3 0.351, snapml 0.046, calories 0.000.
  - **calories fires on almost nothing in real market footage.** Its out-of-taxonomy outputs dominate: Cherry 779, strawberry 314, peach 302, egg 286.
  - **Chilli clips:** snapml calls chillies "capsicum" in 127/246 frames (G3: 62/246).
- **Still images, G3 val n=402, AP50:** G3 leads on banana, apple, citrus, tomato and carrot. snapml is roughly equal only on lemon_lime (0.119 vs 0.117), capsicum (0.265 vs 0.252, but OIV7-leak-risk rows included) and potato (both about 0). calories scores 0 on most classes.
- **Coverage gaps:** small objects are not covered (the synthetic det clip has no primary object under 2% of the frame). Low light is covered only by the two darkest dev clips (c018de016 Colombia fruit vendor, mean luma 56; cfb66f6d2 night market, luma 80), where no model produced more than 1 box in 193 sampled frames, plus one dark texture segment.

## Caveats (fairness)
- **These comparisons favour G3:**
  - G3 val and the synthetic DEV clips come from G3's own model-selection data (COCO/LVIS style).
  - Both candidates also suffer domain shift: calories was trained on studio/tabletop photos, snapml on 416-px OIV7-style images.
  - Even on the neutral VB8 dev web clips, G3 still leads.
- **calories "oren"** (2,360 training instances; 8/8 sampled images show oranges) is unmapped, per the brief. That costs calories citrus recall. A sensitivity run with oren→citrus was not done, because the brief fixed the map. Banana, apple and the other classes still trail badly either way.
- **Latency** is sandbox x86 CPU, not a phone. VB8 replay latency includes a low-conf NMS used for dumping.
- **Interrupted runs:** two sandbox restarts interrupted runs (they were resumed). The first still-image run failed on `np.trapz` (removed in numpy 2) and was fixed. No step looped more than twice.

## Winner checks (requested for a winner; there is none, so recorded only for reference)
- **Checkpoint download rights:** the ONNX is served to any free API key through Roboflow's model endpoint, for self-hosted inference. Redistribution rights were not established, so the weights are kept out of git.
- **Architecture licence:** snapml is GPL-3.0 and calories is AGPL-3.0. Roboflow's commercial licence covers these only on paid plans (https://roboflow.com/licensing). That is acceptable for an academic FYP; G3 is already AGPL through Ultralytics.
- **Export:** ONNX is available directly (that is what was benchmarked). TFLite was not tested. calories is a standard Ultralytics YOLOv8s ONNX, so the usual onnx2tf path should apply, but this is unverified. snapml is a 2022 Roboflow YOLOv5 ONNX with no PyTorch weights.
- **Offline Android:** feasible in principle via ONNX Runtime Mobile, since both ONNX files are static-shape. calories (YOLOv8s, 44.8 MB, about 300 ms on a 2-vCPU sandbox) is heavy for a phone. Not tested on device.
