# G3: gauntlet iteration 3 (2026-10-12, Kaggle T4 for training + CPU sandbox for eval)

Training: Kaggle free T4 (3 detectors, 5-run classifier sweep). **All evaluation, latency and gauntlet numbers: sandbox CPU, 2 cores aarch64, onnxruntime.** This is not a phone and not an emulator. During the G3 gauntlets another workspace job (a Chromium test run) shared the CPU, so the realtime replay dropped many frames for the 384-640 px detectors; this is flagged per row and analysed in G3_failures.md.
Proof level is unchanged: level 4 (validated on a public locked test) for the classifier only. The detector is still below usable.

**Bottom line.** Under the original strict rule no G3 detector is promoted. Under the combined view the user asked for (pooled 829-image mAP50 incl. the new classes + video gauntlet + negatives), **G3 yolo11n@480 is promoted and G3 counts as overall better than G1** (pooled 0.314 vs 0.095, fewer false alarms on both negative clips, same detection segment accuracy), at the cost of test_rf citrus/capsicum regressions, more label flicker and higher CPU latency. The G3 classifier (E224) is promoted under both views. See "Combined view" below.

- **minAreaFrac default -> 0.01** (the optimum for the champion detector and for G3 yolo11n; 0.02 for the others, and 0.01-0.02 cost no DEV segment accuracy).

- **G3 hard negatives on DEV:** the same yolo11n recipe went from 114.5 FA/min (G2 weights) to 1.25 FA/min (G3 weights) before any guard.

## Promotion decision
Rule (G2, unchanged): promote only if better on test_rf AND the gauntlet, with no per-class test_rf regression above 1 pt; G3 addition: no worse FA/min on the new (G2 negtest) negative clip than the champion.

- **Detector (strict rule): G1 stays champion; no G3 detector passes.** (The combined view below overrides this for G3 yolo11n@480.)
  - G3 yolo11n@480: test_rf 0.355 > 0.323 and better negative FA (G1 neg 1.25 vs 2.5-3.75, negtest 0.00 vs 0.75-1.88), quality-graded acc 92.9% vs 84.6%. But det segment accuracy only ties (62.5%), det static flicker rises 0.00 -> 2.29, and **citrus (-15 pts), capsicum (-7 pts) regress** on test_rf. Fails the per-class rule.
  - G3 yolo26n@640: test_rf 0.341 > 0.323 but det segment accuracy 54.2% < 62.5%, citrus -26, apple -7, capsicum -8. Fails.
  - G3 yolo11n-480ms@384 (the deploy-size rule candidate): test_rf 0.365 > 0.323, citrus up (0.90), runs in real time on this CPU (det p50 34 ms, 11% frames dropped). But det segment accuracy 58.3% < 62.5%, G1-neg-clip FA 7.5/min (worse), apple -10 and capsicum -3 pts on test_rf. Fails.
- **Classifier: G3 E224 promoted to champion** (T = 0.25). Crop rotten recall 0.983 -> 0.992 (gate >= 0.983 met), proxy acc 0.978 -> 0.981, low-light rotten recall 0.857 -> 0.941, held-out tube_light_hard acc 0.707 -> 0.978, and on the gauntlet (G1 detector + guard) quality-graded acc 84.6% -> 92.3% with the same rotten segment recall (0.75) and grade flicker 0.00. Costs: one more rotten test image missed (0.992 -> 0.983, within CI), worse calibration (T fitted on a saturated VAL), 224 px input (full pipeline p50 18.9 ms in the gauntlet run, no slower than G1 in that run).
- **Scene guard: promoted as code default (6, 0.01).** With the G1 detector it costs nothing on the G1 clips (62.5% det segments, same quality metrics). Its FA benefit on the locked clips is within replay noise (negtest 0.75 and 1.88 vs 1.88 without; G1 neg clip 3.75 vs 2.5), so it meets "no worse on the new negative clip" only within noise; on DEV it cuts FA for every detector.

How to read it:
- Pooled boxes are dominated by the crowded locked test (banana alone has 5 123 instances), so the shared-class mean mostly tracks the locked test.

**Does G3 count as overall better? Yes, under the combined view.** The G3 yolo11n@480 detector handles 11 of 12 classes instead of 9, scores 3.3x G1 on the pooled 829-image set, has fewer false alarms on both negative clips, and does not lose detection segments on the video gauntlet. Under the original strict rule it is still **not** better, because citrus (-15 pts) and capsicum (-7 pts) regress on test_rf and it does not beat G1 on gauntlet segments. Against G2's best candidate it is better on the pooled score and the negatives but worse on the shared classes and the locked test. Its CPU latency and flicker must be checked on a phone before any product use. The phone, emulator, Lahore data and human-grade gates remain unverified.
