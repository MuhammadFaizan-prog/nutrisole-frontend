# G6: gauntlet iteration 6 (2026-10-13, Kaggle free T4 for training + sandbox CPU for eval)

Training: the two detector fine-tunes ran on **Kaggle free tier, Tesla T4** (one seed each). **Every evaluation, latency and gauntlet number in this report is sandbox CPU (2 cores aarch64, shared with other jobs; PyTorch CPU for mAP, onnxruntime for video)** unless a row says Kaggle T4. Nothing here is a phone, an emulator, Lahore data or human grading; those remain **unverified** (see `G6_device_validation_pending.md`).

Pre-registration (rules before results): `docs/cv/gauntlet/G6_prereg.md` (commit cb9e1ba), with one budget deviation written at 03:35 PKT before any ByteTrack or fine-tune result was seen (DEV tracker grid on the DEV det clip only; TEST r1 first, r2 only if ByteTrack passes r1; candidate gauntlet only if the strict image rule passes).
Interruptions: one sandbox restart (~03:30 PKT) and one workspace rollback; every job is idempotent (on-disk markers) and was relaunched, nothing was re-run selectively to change an outcome.

**Bottom line.**
- **Detector: no promotion. The G3 control (yolo11n trained 640, deployed 480, raw + class-wise NMS 0.7) stays champion under both the strict and the combined view.** rp (replay) pooled 0.299 and rpx (replay + OIV7c + guava + whole capsicum) pooled 0.310 are both below G3's 0.314 (n=829) and both fail the strict per-class rule; neither earned a gauntlet run under the pre-registered gate.
- **Quality classifier, scene guard, rubric: unchanged** (G3 E224, T=0.25; guard rule 2 off).
- **Tracker:** **IouTracker stays the app default; ByteTrack is not adopted.** ByteTrack (buffer 15, picked on DEV) is non-inferior on the fixed-frame TEST gauntlet and r1 = r2 is identical: det segments 0.667 = 0.667, FA/min 1.25 / 0.00 = control, static label flicker 0 = 0, quality acc 0.929 = 0.929, rotten segment recall 0.875 = 0.875; better det frame acc (0.532 vs 0.496) and fewer ID switches (det 30 vs 43, quality 11 vs 27). But the pre-registered rule also requires grade flicker to **fall**, and it is 0.000 for both (floor), so it is not met; time-to-first-correct p90 is also slower (933 vs 760 ms on the det clip). It stays an eval-time option behind a flag (`--tracker-kind`, default `iou`).
- **Ripeness, web-mandi labels, phone validation: deferred to G7** (see "Deferred").

## 6. Promotion decision
- **Strict view: no detector promotion.** Both candidates drop > 0.02 mAP50 on supported classes vs G3 (rp 6 cells, rpx test_rf apple and tomato) and both have pooled below 0.314.
- **Combined view: no detector promotion.** rpx's real gains (test_oiv7c 0.634 -> 0.784, lemon_lime 0.46 -> 0.75, test_oiv7 +0.048, guava 0.932 on the Kaggle-side split) do not offset a lower pooled score, the test_rf apple/tomato losses and a missing video gauntlet; it is a single seed. rp shows that continuing training of G3 on its own data already costs ~0.015 pooled, so part of rpx's per-class movement is fine-tune drift, not data.
- **Tracker: IouTracker stays.** ByteTrack is non-inferior on every TEST video metric (r1 = r2) and better on frame accuracy and ID switches, but the pre-registered rule needs grade flicker to fall and it cannot (0 for both); TTFC p90 is slower. Decision is the strict reading of the pre-registration; it is a floor effect of the synthetic clips, not evidence ByteTrack is worse. Recommended next: port behind an app flag (off) and decide on labelled real footage / phone (G7).
- **Champion after G6:** detector G3 control (unchanged), quality G3 E224 T=0.25 (unchanged), scene guard rule 2 off (unchanged), tracker IouTracker scoreAlpha 0.2 (unchanged; ByteTrack eval-only behind `--tracker-kind`). Guava stays **unsupported** in the app (no promoted model detects it).
