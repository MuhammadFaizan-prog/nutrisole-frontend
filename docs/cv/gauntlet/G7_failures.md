# G7 failures (sandbox CPU numbers, 2-core aarch64 shared; Kaggle T4 for training; not phone / emulator / Lahore / human-graded)

1. **From-scratch training on the rpx mix does not beat G3 overall.** sA / sB (seeds 0 / 1) reach pooled mAP50 0.282 / 0.286 vs G3 0.314 (n=829, PyTorch CPU, imgsz 480); rfs 0.311. The pooled view is dominated by the locked `test` split (557 of 829 images), where sA / sB lose 0.015-0.025 (0.199 / 0.209 vs 0.224) because they detect fewer small objects (size-bucketed recall at 480: 0.235 / 0.231 vs G3 0.301; 12-24 px bucket 0.21 / 0.20 vs 0.31). Hypothesis (G8 to test, not established): the added OIV7c / guava / capsicum images are mostly large, centred objects, shifting the anchor-free head toward larger boxes; RFS partly undoes it (rfs `test` 0.224 = G3, small6 0.248 vs 0.249).
2. **G3-domain classes regress on test_rf in every arm.** banana -0.10 to -0.13, tomato -0.09 to -0.10 (n = 75 / 122 boxes, 22 capture sessions) in sA, sB and rfs; apple -0.06 / -0.07 in sA / sB. The rfs apple/tomato sampling floor fixed apple (0.27 -> 0.35) but not tomato, so the tomato loss is not only sampling share. Both seeds fail the same cells, so this is systematic, not seed noise.
3. **Seed noise is as large as typical "wins".** sA vs sB differ by 0.04 mAP50 on test_oiv7 (n=123) and by up to 0.13 on single classes with 20-50 instances. Any single-seed result from G5-G6 (e.g. per-class gains of 0.05-0.10 on OIV7) is inside that band.
4. **Guava does not transfer.** The from-scratch arms score 0.94-0.96 mAP50 on the same-source guava split inside Kaggle but are poor on the independent Larkana guava set (see G7.md section 10; sB guava-present rate 0.541 vs G6rpx 0.993), calling guava "mango". 300 training images from one source are not enough; in-source test splits overstate generalisation.
5. **The citrus ambiguity rule cannot catch confident mistakes.** G3 labels lemons "citrus" with median score 0.81 and near-zero lemon score at that anchor; the rule cut lemon wrong labels by only 4.7% (needed 30%). Data (rpx mix) cuts them ~3x instead.
6. **No labelled real video.** 69 independent web recordings exist, but 0 are human-verified and auto-label proposals cover 12 / 69 clips, so G7 still has no real-video accuracy number; the fixed-frame gauntlet is synthetic (built from locked test images) and has little headroom (24 segments; grade flicker and FA already at floor for G3).
7. **Compute / infra.** Six sandbox restarts in one day (two with a short workspace rollback). Kaggle: rfs v1 / v2 died within 5 minutes with empty logs (container OOM from `cache="ram"` on the RFS-duplicated list; fixed with disk cache in v3); night v1 failed (`cls_g3.tar` auto-extracted by Kaggle; fixed in v2); the 2-session GPU cap serialised the arms. A post-processing bug (relative `best.pt` path plus an unconditional done-marker) silently produced empty sA / sB evals for ~1.5 h before it was found; markers are now written only when every step succeeds.
8. **Budget cuts at the early closeout.** Auto-label stage 1 stopped at 12 / 69 clips; OWLv2 stage 2, merge and the review queue were not run; the ripeness hue-shift table (part of that kernel) is missing; see G7.md for the tune grid and night-classifier status.
9. **Nothing measured on a phone, an emulator, Lahore footage or by human graders.**
