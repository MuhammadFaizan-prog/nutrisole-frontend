# G6 failures (sandbox CPU numbers, 2-core aarch64 shared; not phone / emulator / Lahore / human-graded)

1. **Replay fine-tune from G3 lowers the score.** rp (G3 checkpoint + exactly G3's train mix, 40 ep, lr0 0.002, Kaggle T4) gets pooled mAP50 0.299 vs G3 0.314 (n=829, PyTorch CPU, imgsz 480) and fails the strict rule on 6 class/split cells (test_rf apple -0.077, banana -0.041, tomato -0.028, citrus -0.022; test_oiv7c citrus -0.028, lemon_lime -0.023). Kaggle val@480 was flat (0.426 vs G3 0.428). Continuing to train the G3 checkpoint on the same data drifts rather than improves; it also means part of any candidate's per-class change is fine-tune drift / single-seed noise, not data.
2. **New data helps where it lands, hurts elsewhere.** rpx (rp + OIV7c + guava + whole capsicum) lifts test_oiv7c 0.634 -> 0.784 (lemon_lime 0.46 -> 0.75) and test_oiv7 0.381 -> 0.429, but pooled stays below G3 (0.310 vs 0.314) and test_rf apple (-0.070, n=25 boxes) and tomato (-0.023, n=122) break the strict rule. Pooled is dominated by `test` (557 of 829 images), where rpx is 0.218 vs 0.224.
3. **Only one seed per candidate.** Two free Kaggle GPU sessions allowed one run each; under the pre-registration a single seed could at best be provisional. Neither candidate reached that point.
4. **ByteTrack wins on DEV are mostly not visible on TEST.** DEV (det clip): segments 0.542 -> 0.625, static flicker 5.0 -> 0.63, ID switches 68 -> 20. TEST: det segments unchanged (0.667 = 0.667), static flicker already 0, false alarms unchanged; the gain is frame accuracy and fewer ID switches. Time-to-first-correct p90 gets worse (760 -> 933 ms on the TEST det clip). The pre-registered adoption rule needs grade flicker to fall, but it is already 0.000 for the control on these synthetic clips, so ByteTrack cannot pass however good it is: the TEST set has no headroom on that metric. 24 synthetic segments cannot resolve a 1-segment (4 pt) difference either.
5. **Compute / infra.** Sandbox CPU shared with other agents' jobs (load ~10 on 2 cores; G3 det p50 177-225 ms during the DEV grid vs ~45 ms later), forcing the pre-registered budget cut (DEV grid on the det clip only). One sandbox restart (~03:30 PKT) and one workspace rollback; jobs were relaunched idempotently from on-disk markers. A second restart (~04:30 PKT) killed the ByteTrack r2 run mid-way; it was re-run from scratch. The ripeness rerun on Kaggle CPU did not finish within the session.
6. **No real-world measurement.** The web-mandi benchmark (Wikimedia Commons, 15 holdout clips) is unlabelled, so no accuracy number exists on real footage; the label-free stability proxy cannot decide adoption. No phone, no emulator (no /dev/kvm), no Lahore data, no human grading.
