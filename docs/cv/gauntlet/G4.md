## G4.1 Deterministic gauntlet + tracker + scene guard
**New fixed-frame mode** (`ml/eval/video_gauntlet.py --no-realtime [--stride N]`): every frame is processed on a fixed schedule (stride 1 = every frame), so results do not depend on CPU load. Latency is still recorded but is informational only (the CPU was shared). Script: `/workspace/work/cv/g4_gaunt.sh` (G1 clips + G2 negtest clip). `--tracker '{json}'` overrides tracker params.

**Reproducibility:** each champion was run twice. Every accuracy, flicker and FA metric was **identical** between runs (G1 champion r1/r2, G3 champion r1/r2); only latency differed (G1 det p50 17.7 vs 24.7 ms). In G3 the realtime replay varied by ~1 FA/min and ~2.5 flicker/10 s between identical configs.

Decisions (rules stated in G3_next.md before these runs):
- **Tracker DEV tune: not adopted.** It lowers label flicker (det all-phase 1.48 -> 1.05, quality static 4.06 -> 3.75). But it makes grade flicker worse (0.00 -> 0.62 /10 s), lowers det frame accuracy (0.470 -> 0.463), and slows TTFC p90 (760 -> 900 ms). That fails "flicker improves without losing accuracy". The code defaults stay scoreAlpha 0.2 (Python and TS unchanged, parity fixture unchanged).
- **Scene guard rule 2 (maxSameClass): turned off** (default 0 in `ml/eval/scene_guard.py` and `native/src/cv/pipeline/postprocess.ts`). On the deterministic replay, turning it off gains one det segment (0.625 -> 0.667) and +2.6 pts frame accuracy, with identical FA on both negative clips. DEV preferred off in G3 too. Cost: all-phase det flicker 1.48 -> 1.79 /10 s (static flicker stays 0). Rule 1 (minAreaFrac 0.01) stays. All later G4 gauntlet rows use the new default.
- In fixed-frame mode the G3 champion shows 0.00 static det flicker (2.29 in the G3 realtime replay) and 0.875 rotten-segment recall (1.00 realtime). The G3 realtime numbers were partly frame-drop artefacts.

## Promotion decision
Rules (stated in G3_next.md before G4 results): **strict** = better test_rf AND fixed-frame gauntlet det segments not worse, no test_rf per-class regression > 1 pt vs G1, no worse negtest FA. **Combined** = pooled n=829 mAP50 + fixed-frame gauntlet + both negative clips + neg_test image rate, compared with the current champion (G3 control).

### Strict view
- **G3 control:** still fails the per-class rule vs G1 (citrus -15.5, capsicum -7.6, apple -1.3), as in G3.
- **A1 hygiene off:** passes the per-class rule vs G1 (no class down > 1 pt) and test_rf (0.406 > 0.323), but **fails the gauntlet**: det segments 0.458 vs G1 0.625 / control 0.667, negtest FA 1.50 vs control 0.00. Not promoted.
- **A2 bg15:** fails per-class vs G1 (capsicum -8.5, citrus -1.2) and negtest FA (0.38 vs 0.00). Not promoted.
- **det-v4 / det-v4hyg (test-informed):** no result; still running on Kaggle at 14:05 UTC. Deferred to G5.
- **cls4 (classifier gates: item-crop rotten recall >= 0.983, synthetic low-light rotten recall >= 0.95):** passes both (0.992, 0.975). **Not promoted, by judgment:** the held-out night_sodium_hard rotten recall drops 0.983 -> 0.941 (7 vs 2 of 119 rotten missed) and tube_light_hard 0.992 -> 0.966, while the video gauntlet is identical. A classifier that trades held-out rotten recall for in-family gains is not a safe swap without phone/Lahore data.
- **Strict-rule result: no G4 candidate passes.**

- **A1:** wins the pooled score and neg_test images but loses 5 of 24 det segments and has 5x the false alarms on the G1 neg clip. Not promoted.
- **A2:** ties det segments, better frame accuracy, but worse pooled score and more false alarms. Not promoted.
- **det-v4 / det-v4hyg:** not evaluated (deferred).
- **Combined-view result: the G3 control (yolo11n@480 + G3 E224, T=0.25, guard rule 2 off) stays champion.**

**Does G4 count as better than G3?** As a model, **no**: nothing was promoted. As an iteration, it made the gauntlet deterministic (the G3 replay noise of ~1 FA/min is gone), turned off a guard rule that cost a segment, showed that the still-image and video signals disagree for the hygiene step, measured a zero-shot teacher that beats every trained detector on test_rf, and found the ripeness label bug before any model shipped.
