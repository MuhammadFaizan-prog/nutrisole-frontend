## G4.1 Deterministic gauntlet + tracker + scene guard
**New fixed-frame mode** (`ml/eval/video_gauntlet.py --no-realtime [--stride N]`): every frame is processed on a fixed schedule (stride 1 = every frame), so results do not depend on CPU load. Latency is still recorded but is informational only (the CPU was shared). Script: `/workspace/work/cv/g4_gaunt.sh` (G1 clips + G2 negtest clip). `--tracker '{json}'` overrides tracker params.

**Reproducibility:** each champion was run twice. Every accuracy, flicker and FA metric was **identical** between runs (G1 champion r1/r2, G3 champion r1/r2); only latency differed (G1 det p50 17.7 vs 24.7 ms). In G3 the realtime replay varied by ~1 FA/min and ~2.5 flicker/10 s between identical configs.

Decisions (rules stated in G3_next.md before these runs):
- **Tracker DEV tune: not adopted.** It lowers label flicker (det all-phase 1.48 -> 1.05, quality static 4.06 -> 3.75). But it makes grade flicker worse (0.00 -> 0.62 /10 s), lowers det frame accuracy (0.470 -> 0.463), and slows TTFC p90 (760 -> 900 ms). That fails "flicker improves without losing accuracy". The code defaults stay scoreAlpha 0.2 (Python and TS unchanged, parity fixture unchanged).
- **Scene guard rule 2 (maxSameClass): turned off** (default 0 in `ml/eval/scene_guard.py` and `native/src/cv/pipeline/postprocess.ts`). On the deterministic replay, turning it off gains one det segment (0.625 -> 0.667) and +2.6 pts frame accuracy, with identical FA on both negative clips. DEV preferred off in G3 too. Cost: all-phase det flicker 1.48 -> 1.79 /10 s (static flicker stays 0). Rule 1 (minAreaFrac 0.01) stays. All later G4 gauntlet rows use the new default.
- In fixed-frame mode the G3 champion shows 0.00 static det flicker (2.29 in the G3 realtime replay) and 0.875 rotten-segment recall (1.00 realtime). The G3 realtime numbers were partly frame-drop artefacts.
