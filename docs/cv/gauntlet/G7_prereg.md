## 3. ByteTrack (G6_next item 4) - post-hoc rule, written knowing the G6 TEST numbers
Honest framing: the G6 TEST runs (test_iou_r1, test_bt_r1, test_bt_r2) were already seen, so this rule **cannot be confirmatory**; its outcome is labelled post-hoc/exploratory and can only make ByteTrack the *recommended candidate for the phone / labelled-real-footage A/B*. The app default stays IouTracker (flag OFF) whatever the outcome.
Movable rule (all on the G1 TEST det clip unless stated): det seg acc not lower; FA/min not higher on G1 neg and G2 negtest; quality acc and rotten seg recall not lower; ID switches (det clip) at least 20% fewer; det frame acc not lower; TTFC p90 <= 1000 ms absolute (sub-second product target) and not more than 25% above the control; r1 = r2 on all non-timing fields.
Port: association step to `native/src/cv/pipeline/` behind a flag defaulting OFF (`trackerKind: 'iou' | 'bytetrack'`), with a Python-generated TS parity fixture (like `tracker_parity.json`) and tests; IouTracker output must be byte-identical with the flag off.

## 4. Citrus ambiguity UX (G6_next item 6)
Output "citrus (lemon/orange?)" when the top detection class is lemon_lime or citrus and the other class's score at the same location is close: implemented on the raw head (per-anchor class scores of the kept box) as `other >= r * top`, behind config (default OFF). r is chosen on **OIV7c val** (never test) from {0.3, 0.4, 0.5, 0.6, 0.7} to maximise (wrong-hard-label reduction) subject to ambiguous rate on correctly-labelled items <= 25%; then measured once on test_oiv7c (n=181, G3 control, imgsz 480, CPU): per GT lemon_lime/citrus matched at IoU >= 0.5: correct / ambiguous-containing-truth / wrong. Recommend enabling if test_oiv7c wrong-hard-label rate on lemon_lime GT drops >= 30% relative and ambiguous rate on correctly-labelled items <= 25%.
